# Telegram-бот "Відбій + розклад"

Бот следит за воздушной тревогой в выбранной области (через API
[alerts.in.ua](https://alerts.in.ua)) и, как только тревога заканчивается,
пишет в чат «Відбій тривоги» вместе с тем, какой урок идёт сейчас
(или когда начнётся следующий).

## Что нужно получить заранее

1. **Токен бота** — у [@BotFather](https://t.me/BotFather) в Telegram
   командой `/newbot`.
2. **Токен API alerts.in.ua** — зарегистрироваться на
   https://alerts.in.ua и получить бесплатный токен в личном кабинете.
3. **ID чата**, куда бот будет писать сообщения (это может быть
   личный чат с ботом, группа класса или канал). Проще всего узнать
   ID через бота `@userinfobot` (для личного чата) или добавив бота
   `@getmyid_bot` в группу.

## Установка

```bash
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` и впишите туда `BOT_TOKEN`, `CHAT_ID`, `ALERTS_TOKEN`.

## Расписание уроков

`bot/schedule.json` состоит из двух частей:

- **`bells`** — розклад дзвінків: время начала/конца для уроков 1–6.
- **`days`** — расписание предметов по дням (`"0"` = понеділок …
  `"4"` = п'ятниця). Каждый элемент списка — урок по порядку: первый
  элемент = 1-й урок и т.д.

Некоторые предмети чергуються по тижнях місяця (наприклад,
Мистецтво/Музика, Історія/Громадянська освіта). Для такого уроку
замість рядка пишется об'єкт:

```json
{"1_2": "Мистецтво", "3_4": "Музика"}
```

Це означає: на 1-му і 2-му тижні місяця — «Мистецтво», на 3-му і
4-му — «Музика». Якщо предмет є тільки в одній групі тижнів (як
«Підприємництво» у вівторок), другий ключ просто не вказується — в
іншу групу тижнів цього уроку не буде.

Яку саме групу тижнів («1_2» чи «3_4») зараз вважати активною, бот
рахує автоматично за числом місяця. Якщо це не збігається з реальним
журналом школи — задайте вручну через `WEEK_GROUP_OVERRIDE` в `.env`
(`1_2`, `3_4` або `auto`).

**Уроки 7 і 8** тепер мають фіксований час у `bells` (16:10–16:55 і
17:00–17:45), тому враховуються як звичайні уроки — з'являються як
«поточний»/«наступний» так само, як 1–6. Якщо колись час знову
зміниться — просто відредагуйте відповідні значення в `bells`.

## Відмітка скасованих уроків (команди в ЛС боту)

Якщо вчитель скасував конкретний урок — його можна прибрати з
розкладу командами в особистих повідомленнях боту (в групі ці
команди не працюють навмисно):

- `/cancel <номер>` — скасувати урок сьогодні, наприклад `/cancel 3`
- `/cancel <номер> <РРРР-ММ-ДД>` — скасувати на конкретну дату,
  наприклад `/cancel 3 2026-09-10`
- `/uncancel <номер> [дата]` — повернути урок назад
- `/cancelled [дата]` — показати список скасованих на день

Скасований урок пропускається при пошуку «поточного/наступного»
уроку і замість цього потрапляє в окремий рядок повідомлення:
«Скасовано сьогодні: …».

**Ці команди доступні тільки тим, чий Telegram user_id вказаний у**
`ADMIN_IDS` в `.env` (через кому, якщо людей декілька):
```
ADMIN_IDS=123456789,987654321
```
Дізнатися свій `user_id` можна у **@userinfobot**. Без цього
налаштування команди `/cancel`, `/uncancel`, `/cancelled` нікому не
відповідатимуть.

Дані про скасовані уроки зберігаються у файлі
`bot/data/cancellations.json` (в git не потрапляє). На Railway цей
файл живе, поки контейнер не перезбирався заново (новий `git push`
скидає його) — для лёгкого шкільного використання цього зазвичай
достатньо.

## Ранкова розсилка розкладу

Щодня о `MORNING_DIGEST_TIME` (за часом Europe/Kyiv, за замовчуванням
`10:00`) бот сам надсилає в `CHAT_ID` повний розклад на сьогодні —
усі уроки з часом, скасовані позначені окремо. У вихідні (коли
уроків немає) розсилка автоматично пропускається.

Змінити час — задайте `MORNING_DIGEST_TIME=08:30` в `.env`/Variables.
Вимкнути зовсім — `MORNING_DIGEST_TIME=off`.

## Запуск

```bash
python bot/main.py
```

Бот сразу начнёт опрашивать API тревог каждые `POLL_INTERVAL_SECONDS`
секунд (по умолчанию 15) и при отбое пришлёт сообщение в `CHAT_ID`.

Добавьте бота в нужный чат/группу и убедитесь, что `CHAT_ID`
указывает именно туда, куда должны приходить уведомления.

Команда `/now` в чате с ботом в любой момент покажет, какой сейчас
урок по расписанию — удобно для проверки, что всё настроено верно.

## Как это работает

- `bot/alerts.py` раз в `POLL_INTERVAL_SECONDS` секунд запрашивает
  список активных тревог и сравнивает с предыдущим состоянием: если
  для вашей области тревога была активна, а теперь её нет — это
  событие "отбой".
- `bot/lessons.py` по текущему времени (часовой пояс Europe/Kyiv)
  ищет в `schedule.json` урок, который идёт сейчас, либо ближайший
  следующий.
- `bot/main.py` связывает это вместе и отправляет сообщение через
  Telegram Bot API (библиотека aiogram).

## Деплой на Railway (бесплатно, без вашего ПК)

**Важно: `.env` с токенами никогда не заливается в GitHub.** Файл
уже добавлен в `.gitignore`, поэтому `git add .` его не подхватит.
Сами токены вводятся отдельно — через переменные окружения в панели
Railway, а не через файл в репозитории.

1. Создайте **пустой** приватный репозиторий на GitHub и залейте туда
   проект (`.env` при этом остаётся только у вас на диске):
   ```bash
   git init
   git add .
   git commit -m "init"
   git branch -M main
   git remote add origin <ссылка на ваш репозиторий>
   git push -u origin main
   ```
2. Зайдите на [railway.app](https://railway.app), войдите через
   GitHub, нажмите **New Project → Deploy from GitHub repo** и
   выберите этот репозиторий. Railway сам увидит `Dockerfile` и
   соберёт образ.
3. Откройте вкладку **Variables** созданного сервиса и добавьте
   переменные вручную (значения — те же, что у вас сейчас в
   локальном `.env`):
   `BOT_TOKEN`, `CHAT_ID`, `ALERTS_TOKEN`, `REGION_TITLE`,
   `POLL_INTERVAL_SECONDS`, `NOTIFY_ON_START`, `WEEK_GROUP_OVERRIDE`.
4. Сохраните — Railway перезапустит сервис уже с этими переменными,
   и бот будет работать постоянно, независимо от вашего ПК.

Для Render.com шаги аналогичны: **New → Web Service** (или
**Background Worker**) → подключить репозиторий → там же во вкладке
**Environment** задать те же переменные.

## Важно про безопасность токенов

Раз токены уже были показаны в этом чате — на всякий случай стоит их
перевыпустить перед тем, как отдавать проект в постоянную работу:
- Bot Token — у [@BotFather](https://t.me/BotFather) командой
  `/revoke`, он выдаст новый.
- Alerts token — в личном кабинете на alerts.in.ua можно
  перегенерировать.

Это займёт минуту, а привычка не оставлять "живые" секреты нигде,
кроме переменных окружения хостинга, убережёт от случайных утечек в
будущем.
